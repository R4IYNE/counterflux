<objective>
Fix a bug in the reconcile() resume branch of src/services/sync-reconciliation.js where the `sync_reconciled_at:<userId>` meta flag is not set after a successful resumed bulkPull. This causes the populated-populated reconciliation modal to re-appear on the boot AFTER the resumed pull completes, creating a confusing loop for users on large household collections who interrupt a MERGE EVERYTHING bulkPull.

Purpose: Resume-from-interrupted-pull is a successful reconciliation outcome and should be treated identically to the other four classifyState branches (empty-empty, empty-populated, populated-empty, populated-populated post-modal), all of which already call `_markReconciled(userId)` on success. The resume path is the lone gap.

Output: One failing-then-passing regression test in tests/sync-reconciliation.test.js + one new line in src/services/sync-reconciliation.js. No other files touched.
</objective>
