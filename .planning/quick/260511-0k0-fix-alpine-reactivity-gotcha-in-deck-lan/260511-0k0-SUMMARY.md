# Quick Task 260511-0k0: Fix Alpine Reactivity Gotcha in Deck-Landing Summary

One-liner: Pre-init `_cardCount`/`_commanderCard` reactive keys in `loadDecks` + drop `=== undefined` guards and hoist dynamic import in `enrichDecks`, fixing the deck-landing screen rendering permanent `0/100` + gradient placeholder despite correct underlying data.

## The Bug

The Thousand-Year Storm `/decks` landing page rendered the wrong card-count (`0/100` instead of the real `73/100`) and the gradient-placeholder fallback (instead of the commander art crop) on first paint, even when the deck store had hydrated and `enrichDecks()` had run. Confirmed via DevTools probe in this codebase today.

The root cause is a documented **Alpine 3.x reactivity gotcha**: Alpine's reactive Proxy only forms subscriptions for properties that exist on an object **at the moment it's wrapped**. Properties that read as `undefined` on first access are NOT tracked — when something later writes to that key, the Proxy has no subscriber to notify, and dependent `<template x-if="deck._commanderCard">` / `x-text="(deck._cardCount || 0) + '/' + deck.deck_size"` blocks don't re-render.

The two affected keys (`_cardCount`, `_commanderCard`) didn't exist on raw deck rows coming out of Dexie via `db.decks.orderBy('updated_at').reverse().toArray()`, so the Proxy never subscribed. `enrichDecks()` then mutated those keys directly inside a watcher callback — the writes succeeded on the underlying object but never triggered a re-render.

Layered on top of that, `enrichDecks()` had a second bug: its `if (deck._cardCount === undefined)` guard meant that even after the keys were pre-initialised (with `0` as a seed value), re-enrichment was skipped because the value was now `defined-but-stale`. The watcher fired correctly, the function ran, but the body short-circuited on every iteration and Dexie was never re-queried.

## The Two-Half Fix

### Half 1 — `src/stores/deck.js` `loadDecks()` (~L50-62)

```javascript
async loadDecks() {
  const rows = await db.decks.orderBy('updated_at').reverse().toArray();
  // Alpine reactivity gotcha — pre-init the reactive keys deck-landing
  // mutates (`_cardCount`, `_commanderCard`) BEFORE assigning to this.decks.
  // Properties absent at Proxy-wrap time get no subscribers; later writes
  // are silently dropped from the dep graph. See enrichDecks in
  // src/components/deck-landing.js. Do NOT remove this loop.
  for (const d of rows) {
    if (d._cardCount === undefined) d._cardCount = 0;
    if (d._commanderCard === undefined) d._commanderCard = null;
  }
  this.decks = rows;
},
```

The pre-init loop seeds the keys on the raw object **before** Alpine wraps it. Subscriptions form as expected. The inline gotcha comment is load-bearing — it warns future refactors not to drop the loop and is asserted by the static-grep test (`expect(body).toMatch(/Alpine\s+reactivity|reactive\s+keys|Proxy-wrap|gotcha/i)`).

### Half 2 — `src/components/deck-landing.js` `enrichDecks()` (~L108-135)

```javascript
async enrichDecks() {
  const store = Alpine.store('deck');
  // Hoisted — one dynamic import per call, not 2 × N where N = deck count.
  const { db } = await import('../db/schema.js');
  for (const deck of store.decks) {
    if (deck.commander_id) {
      try {
        const card = await db.cards.get(deck.commander_id);
        deck._commanderCard = card || null;
      } catch {
        deck._commanderCard = null;
      }
    }
    try {
      const cards = await db.deck_cards.where('deck_id').equals(deck.id).toArray();
      deck._cardCount = cards.reduce((sum, c) => sum + c.quantity, 0);
    } catch {
      deck._cardCount = 0;
    }
  }
},
```

Three changes:

1. **Hoist the dynamic import** — moved `const { db } = await import('../db/schema.js')` above the `for` loop. One call per `enrichDecks()` invocation, not 2 × N.
2. **Drop the `!deck._commanderCard` guard** — every watcher fire re-fetches the commander card. A deck whose `commander_id` was set after initial load now picks up the card on the next watcher tick.
3. **Drop the `=== undefined` guard around `_cardCount`** — every watcher fire recomputes the card count. The seed value of `0` (from the Half-1 pre-init) gets recomputed back to the real count as soon as Dexie data is ready.

Per-deck `try/catch` boundaries are retained so a single deck's Dexie miss doesn't poison the rest of the list.

## Why the Audit Found No Other Pre-Init Sites

The PLAN.md `<note>` block enumerated every `this.decks` mutation in `src/stores/deck.js` and concluded the single pre-init in `loadDecks` covers every live code path. Restated here for the SUMMARY record:

| Path | Mutation shape | Why no extra pre-init needed |
|------|---------------|------------------------------|
| `loadDecks()` L50 | Direct assignment from Dexie | **THIS is where the pre-init goes.** |
| `deleteDeck()` L258 | `this.decks = this.decks.filter(...)` | `.filter` preserves the existing pre-initialised keys on surviving items. |
| `createDeck()` L68 | Calls `await this.loadDecks()` after `db.decks.add` | Funnels through the pre-init path automatically. |
| `duplicateDeck()` L303 | Calls `await this.loadDecks()` after add + bulk add | Same. |
| `renameDeck()` L309 | Calls `await this.loadDecks()` after `db.decks.update` | Same. |
| `deleteDeck()` undo L279 | Calls `await this.loadDecks()` after restore | Same. |
| `recategorizeAll()` L333 | Calls `await this.loadDeck(deckId)` (note: singular, not plural) | Doesn't touch `this.decks` array — only `activeCards`. |

The defensive `if (d._cardCount === undefined)` inside the pre-init loop means that even if a future refactor somehow flows pre-enriched rows back through `loadDecks`, the existing values aren't clobbered.

## Deferred Work — v1.3 SEED-007 Candidate

This fix is intentionally narrow. The broader reactivity story stays open as a v1.3 candidate:

- **Auto-update on `db.deck_cards` mutations** — the count still requires a manual `loadDecks()` call to recompute. Alpine doesn't observe Dexie directly. Adding a card via the deck builder, returning to `/decks`, and seeing the count update relies on whichever code path triggers the navigation also calling `loadDecks()`. Today that's mostly fine because the navigation-to-decks paths reload the store, but it's not invariant.
- **Refactor enrichment to Alpine computed properties** — instead of mutating `_cardCount` / `_commanderCard` directly, expose them as computed getters on the deck store keyed by `deck.id` with an internal cache. Eliminates the entire reactivity-gotcha class.
- **Audit other widgets** — collection, market, game-tracker, sync-status panels all follow similar enrichment patterns. Probable additional gotchas exist; needs a sweep.

These are tracked as **SEED-007 "Alpine reactivity audit"** for the next `/gsd:new-milestone` (v1.3) discussion.
